# 일기

현재 프로젝트의 코드베이스와 git 히스토리를 분석해서 작업일지를 작성하고, 커밋 후 푸시까지 수행한다.

## 절차

1. **현재 상태 파악**
   - `git log --oneline -20`, `git status --short` 로 최근 커밋과 미커밋 변경사항을 확인한다.
   - 미커밋 변경이 있으면 `git diff`로 실제 내용을 확인한다.
   - 최근 수정된 파일들을 훑어보고, 이번 대화(있다면)에서 나눈 작업 맥락도 함께 반영해 "무엇을, 왜" 바꿨는지 파악한다.

2. **작업일지 작성**
   - 오늘 날짜(YYYY-MM-DD)를 사용해 `docs/작업일지/작업일지-<날짜>.md`에 저장한다 (`docs/` 폴더가 없으면 새로 만든다).
   - 같은 날짜 파일이 이미 있으면 덮어쓰지 말고 내용을 이어서 추가한다.
   - 내용은 코드 스니펫 나열이 아니라, 무엇을 했는지 / 왜 했는지(배경·이유) / 어떤 문제를 어떻게 고쳤는지 / 어떻게 검증했는지를 한국어로 간결하게 정리한다.
   - 확인되지 않은 내용은 추측해서 적지 않는다. git 히스토리·코드·대화 맥락에 근거가 있는 것만 쓴다.

3. **커밋 및 푸시**
   - 작업일지 파일만 `git add`로 스테이징한다. 다른 미커밋 변경이 섞여 있으면 먼저 사용자에게 물어보고 진행한다.
   - 커밋 메시지: `docs: 작업일지 <날짜> 작성`
   - `git remote -v`로 원격 저장소 존재 여부를 확인한다.
     - 원격이 없으면 푸시를 건너뛰고 그 사실을 사용자에게 알린다.
     - 원격이 있으면 현재 브랜치로 `git push`를 실행한다.
   - 푸시가 실패하면(인증 오류, 충돌 등) 강제로 밀어붙이지 말고 원인을 그대로 보고한다.

## 주의
- 작업일지 파일 생성/커밋 외의 다른 코드 변경은 하지 않는다.
- 끝나면 생성한 파일 경로, 커밋 해시, 푸시 성공 여부를 한국어로 짧게 보고한다.
