# Pages 게임 전용 배포

8.4.0의 기존 Pages 배포와 전체 재빌드가 `syncing_files`에서 시간 초과됐다. 같은 주소를 유지하면서 공식 GitHub Actions 배포로 전환한다. 이 변경이 Pages 서버의 장애까지 해결한다고 보장하지는 않는다.

## 묶음

`node scripts/build-pages.cjs`는 HEAD에 커밋된 루트 게임 스크립트·스타일·이미지/음원·두 진입 HTML과 `assets/`를 `_site/`에 복사한다. 문서·원본 자료·실험용 페이지·개발 도구는 공개 묶음에서 제외한다. 로컬 작업 파일이 HEAD와 다르면 HEAD 바이트를 읽어 미커밋 수정이 섞이지 않는다. 심볼릭 링크를 허용하지 않으며 진입 HTML의 직접 리소스 존재와 모든 연결 스크립트의 문법을 확인한다.

8.4.0 기준 911개·249,930,837바이트(238.35MiB). 두 진입 페이지와 게임 에셋을 유지한다. 출력에는 `.nojekyll`과 커밋·버전·파일 수·크기를 기록한 `_deployment.json`을 더한다. 출력 디렉터리가 이미 있으면 덮어쓰지 않고 중단한다.

## 배포

`.github/workflows/pages.yml`이 master 푸시 및 수동 실행에 반응한다. 읽기 권한으로 체크아웃하고 게임 묶음을 업로드한 뒤, Pages·OIDC 권한으로 github-pages 환경에 배포한다. 진행 중인 배포는 새 푸시로 취소하지 않는다. Pages 설정은 branch 자동 빌드에서 workflow 방식으로 바꾸되 사이트 URL을 유지한다.

배포 성공 뒤 `scripts/verify-pages.cjs`가 실제 URL의 배포 커밋과 버전, 대포·좀비 주요 파일 응답을 확인한다. 이 검사까지 통과해야 온라인 반영 완료로 보고한다. 실패하면 성공으로 표시하지 않는다. 같은 HTTPS 호스트와 경로 및 기존 저장 키를 유지한다.

## 검사

`scripts/test-pages-bundle.cjs`는 임시 새 디렉터리에 실제 묶음을 만들고 개발 자료 제외·HEAD 바이트 격리·신규 에셋을 검사한다. 로컬 HTTP 서버에 묶음을 올려 온라인 검증 도구도 실행한다. 기존 우주편 저장 구조와 게임 능력치는 변경하지 않는다.
