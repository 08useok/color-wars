# 8.0 계획: 우주편 3장 + 신레전드 (2026-10-30)

> **사용자 결정(10-30):** 버전이 8.0이 되면 **신레전드 + 우주편 3장**을 만든다. 첫 번째 숫자(8.0.0)는 새 이야기가 열릴 때만 올린다는 규칙(우주편 3장이 그 후보)과 맞다.
> **난이도(10-30):** 이후 새로 만드는 적·스테이지는 원작 수치 그대로가 아니라 **체력·공격 ×1.3**으로 어렵게 만든다(기본값, 사용자가 세기를 안 정해 내가 잡음). 구레전드 41~49장은 원작 그대로.

- 우주편 2장 때와 같은 방식(원작 DB 표 → JSON → 빌더 → 게임 데이터)을 쓸 수 있다. 3장은 2장(적 4종·48맵)과 규모가 같고, 신레전드는 구레전드 41~49장(적 5종·51맵)보다 **훨씬 크다**(275맵, 신규 적 수십 종).
- 신레전드 장 목록: 真・伝説のはじまり(s13000) → まんぷく秘境 → アドベン大森林 → じゃぶじゃぶ旧海道 → ワンワン湾 → 深淵を覗く者 … 人類ネコ化計画(s13047).

## 결정(사용자, 10-30)

- **출시 묶음:** 우주편 3장과 신레전드를 **둘 다 완성되면 8.0.0 한 번에** 낸다. 그 전까지는 7.x 패치로만 푸시한다.
- **신레전드 범위:** **앞부분만 먼저.** 신규 적 수를 확정한 뒤 몇 장까지 넣을지 정한다.

## 신규 적 추정(신레전드, 10-30 DB 조회·기존 번호 지도 대조)

- 신레전드 적 192종 중 기존 번호 지도(106종)에 없는 것은 **88종**이다. 이 중에는 곰 선생(014)처럼 이미 게임에 있지만 지도에 없는 적이 섞여 있어, 실제 신규는 이보다 적다(이름 대조 필요).
- 장별로 새로 등장하는 미확인 적(누적): 0장 3(3) · 1장 3(6) · 2장 5(11) · 3장 4(15) · 4장 2(17) · 5장 2(19) · 6장 1(20) · 7장 4(24) · 8장 1(25) · 9장 2(27) · 10장 1(28) · 11장 1(29) · 12장 4(33) · 13장 2(35). **앞 14장(약 80맵)까지 최대 35종** 수준이고 이후는 장당 0~3종이다.
- 앞 10장(약 55맵)이면 최대 28종 후보, 앞 5장이면 최대 17종 후보다. 모션 굽기·능력 구현은 적 한 종마다 드는 일이라, 범위는 이름 대조로 실제 신규 수를 센 뒤 정한다.

## 제안 순서

1. **자료 확보:** 우주편 3장 48맵과 신레전드 275맵 원본 페이지를 받아 `reference-sheets/`에 보관하고 표를 JSON으로 뽑는다(`fetch-cosmos2.cjs`·`fetch-legend-41-49.cjs`를 본뜬다). 적 이름 대조로 실제 신규 적 수를 확정한다.
2. **신규 적:** 모션 굽기(`bc-enemy-anim`) + 능력 구현 + **×1.3** 적용. 이미지 내려받기는 그때마다 승인.
3. **우주편 3장 등록:** 스테이지 목록 **맨 끝**에 붙인다(저장된 클리어 번호가 밀리지 않게). **저장된 진행도 합치기가 필요하다**(7.1.1에서 고친 우주편 2장 저장 오류와 같은 구조: `game.js`가 진행도를 먼저 읽을 때 새 범위를 모른다). 잠금·탭·억제기·별 에이리언 배율·보물 3장 연결.
4. **신레전드 등록:** 구레전드 40~49장처럼 레전드 탭에 새 묶음으로 붙인다. 구레전드 ★1 완주 뒤에 열리는지(또는 우주편 3장 뒤인지)를 정한다.
5. **시험·난이도:** 강한 덱 한 판 시험, ×1.3 결과 확인, 저장 복원·순차 해금 시험, 기존 번호 불변 시험.
6. **8.0.0 공지·푸시.** 그 전까지는 7.x 패치로만 푸시한다(7.3 묶음이 먼저).

## 같이 풀리는 것

- **우주편 보물 2/3 연결**(오래 남은 질문): 우주편 3장이 생기면 보물 3/3을 3장 최종 클리어에 연결하는 것이 자연스럽다.
- **한 가지 위험:** 신레전드 신규 적이 많으면 모션 굽기와 능력 구현이 가장 오래 걸린다. 적 수가 확정되면 나눠서(앞 장부터) 내거나, 우주편 3장을 먼저 8.0.0으로 내고 신레전드를 8.1로 미룰지 다시 정한다.
