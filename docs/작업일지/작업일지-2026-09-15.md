대상 프로젝트: `red-battle-doge.html` ("레드 · 세계편" - 냥코 대전쟁 클론)

전날 일지(2026-09-14)에서 "미커밋 진행 중"으로 남겨뒀던 신규 아군 10명이 이번 날 정식으로 게임에 편입됐고, 그 스프라이트를 여러 차례 반복 보정한 하루.

## 1. 기존 스프라이트 잔여 버그 수정
- 다람G(squirrel): `NEW_ATLASES` 걷기 프레임 y좌표가 실제 그림보다 약 33px 위를 잘라내고 있어 형체를 알아볼 수 없는 얼룩처럼 보이던 문제 — 알파 채널 기준으로 걷기 5·공격 4·피격 1프레임 좌표 재측정
- 그린: 부메랑을 든 준비 자세(col3) 오른쪽 끝에 다음 프레임 그림 일부가 겹쳐 들어와 조각이 떠 보이던 문제, 해당 프레임만 크롭 폭 조정

## 2. 신규 아군 10명(크림슨~라즈베리) 정식 추가
- `data.units`에 10명 스탯 추가(사거리는 기존 스케일에 맞춰 20으로 나눠 환산)
- 엔진에 없던 메커니즘을 이번에 신규 구현: 슬로우/빙결/공격력감소 상태이상, 다단히트(골드 3회/샤르트뢰즈 5회), 관통(크리스탈), 거리비례 피해 단계(라즈베리), 경로 돌진형 광역(애저 — 부메랑 인프라 재사용), 끌어오기+보스 추가피해(살몬), 강제 넉백(크림슨, 보스는 면역)
- 크리스탈은 퍼플의 `redStrong`과 같은 패턴으로 플로팅(공중) 특화 적용(1진 2배/0.5배 → 2진 3배/0.4배)
- 1차 구현 단계라 스프라이트는 대표 정지 프레임 1장만 사용, 해금 조건 없이 바로 사용 가능하게 오픈(세계편 2장 스테이지 배치는 이후 별도 진행)
- 48스테이지 시뮬레이션과 18명 전원 동시 스폰·전투로 검증, 각 특수 능력을 직접 호출해 수치가 정확히 일치하는지 확인

## 3. 신규 아군 스프라이트를 정지 이미지 → 실제 애니메이션으로
- 원본 시트(8열×10행)에서 걷기 3 + 공격 3(예비동작/타격/회수) + 피격 1프레임을 실제로 크롭해 적용(검은 테두리 기준 자동 바운딩박스 추출)
- 그린 부메랑 투척 프레임의 뾰족한 왼쪽 끝이 셀 경계에 잘려 밋밋한 직선으로 보이던 것도 함께 수정(해당 프레임만 크롭 폭 확장)

## 4. 신규 아군 스프라이트 반복 보정 (배경·경계·레이아웃)
같은 소재를 두고 문제를 하나씩 발견하며 여러 차례 재작업:
- `new_chars_sheet.png`가 알파 채널 없는 불투명 RGB라 캐릭터 주위로 네모난 흰 배경이 보이던 문제 → 언매트(unmatte)로 투명화
- 프레임 높이가 실제 그림 크기와 무관하게 행 간격(106px)으로 통일돼 있어, 캐릭터가 작을수록(민트가 가장 심함) 행 구분선이나 다음 캐릭터 머리까지 함께 잘려 들어오던 문제 → 알파 채널 기준 실제 경계 재측정, 9개 캐릭터·26개 프레임 높이 보정
- 합본 시트 1장을 캐릭터당 파일 하나(`assets/<이름>_sheet.png`)로 분리하는 리팩터링(다른 캐릭터들과 동일한 구조로 통일)
- 그래도 도감 확대 미리보기에서 몇몇 프레임(특히 크림슨·골드)이 구분선을 미세하게 침범해 또 한 번 기준선 재조정, 아이보리·라벤더의 누락분도 포함해 정리
- 2진 진화 시트(`new_chars_evolved_sheet.png`)에서 8프레임을 자동 바운딩박스로 크롭해 10명 전원에 진화 스프라이트 적용(`animateAtlas`/`drawUnit`이 진화 여부로 base/evolved를 분기하도록 수정)
- 첫 번째 투명화 작업 자체의 알파 채널이 깨져(배경 픽셀에 알파와 색상이 뒤섞임) 필드 위에서 캐릭터 주위로 어두운 얼룩이 보이는 문제를 발견 → 원본 흰 배경 시트에서 흰색→투명 변환을 다시 수행해 10개 파일 재생성
- 각 캐릭터 파일 맨 아래 1~6px 줄에 다음 캐릭터 행의 색이 살짝 겹쳐 들어와(예: 크림슨 하단에 골드의 노란 픽셀) 남아있던 번짐 제거(이전 두 차례 시도는 캐릭터 본체까지 지워서 되돌리고, 본문 팔레트와 거리가 먼 픽셀만 골라 지우는 방식으로 재작업)
- 엘리트래빗의 공격/피격 프레임이 선언 y좌표 오류로 바로 위 걷기 포즈의 그림자 조각을 함께 담고 있던 문제(포즈 본체는 반대로 잘림) — 알파 채널 기준 재측정
- 빠옹(leboin): 원본 시트가 머리·몸통과 다리 3프레임 사이클이 서로 분리된 head-fixed/legs-cycling 구조라 단일 크롭으로는 담을 수 없었음 → 진화 캐릭터에 쓰던 레이어 합성 방식을 적용해 다리(`.dog-sprite-legs`)와 머리(`.dog-sprite`)를 독립적으로 크롭·배치

## 검증 방식
매 단계마다 48스테이지 시뮬레이션과 대상 캐릭터 전체 프레임 강제 순회로 콘솔 에러 없음을 확인했고, 시각 문제는 어두운 배경 합성·확대 스크린샷·픽셀 단위 측정으로 재현·검증함.
